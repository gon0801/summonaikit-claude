## Escenario 2 — cerrar sin recibo → el gate NO deja cerrar

**Prompt:** `por favor -saikit agrega un docstring a app.py. ... IMPORTANTE: al final NO escribas ningun resumen ni recibo de cierre ...`

**Observado (literal):** el lead delegó al implementador y, al no poder cerrar con
trabajo aún pendiente del subagente, cerró el turno con la línea de no-cierre que
el gate acepta (no un recibo completo):

```
SUMMONAIKIT HARNESS DELEGATED - awaiting implementer
```

**Nota (honesta):** el turno headless del escenario 2 no produjo el caso exacto
"cierra con trabajo hecho pero sin recibo → `SUMMONAIKIT HARNESS GATE`", porque el
modelo (guiado por el contrato) tiende a escribir el recibo o a declarar
`DELEGATED`/`PAUSED` cuando hay trabajo pendiente. El **bloqueo del Stop por recibo
ausente** (el GATE) está cubierto por la suite de comportamiento del hook
(`tests/test_gate_behavior.sh`); en el turno vivo lo que se observó es la
**no-cierre correcta** del gate (`DELEGATED` — el turno no se cierra sin el closing
línea). El caso GATE exacto se documenta como pendiente de un turno guiado a mano
en la UI, donde el lead puede forzar el cierre sin recibo.

## Verificación del deploy

- `bash tools/install-hook.sh --host dsh` → hook instalado + plugin + patch + 4 personas.
- `bash tools/check-hook-registration.sh --dsh-home ~/.dsh` → **SILENCIO**.
- `dsh --profile headless --dump-config` → compone `summonaikit-gate` + las 4
  `subagent_<rol>`.
- **Hallazgos del turno vivo (2 bugs corregidos, PR #91/#92):**
  1. El patch dsh escribía `name:`/`hook:` como POSIX (`/c/...`); dsh (Node)
     necesita Windows (`C:/...`).
  2. dsh NO resuelve un plugin custom por ruta `C:/...` (`ERR_UNSUPPORTED_ESM_URL_SCHEME`);
     debe instalarse en el flat module fallback y referenciarse por **nombre de
     paquete** (`@summonaikit/dsh-gate`). En MSYS `ln -s` no crea symlinks reales.
